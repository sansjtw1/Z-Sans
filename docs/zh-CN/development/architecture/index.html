Architecture Overview

上一页 下一页

Z-Sans 采用模块化设计：核心功能与工具实现分离，引擎负责调度，繁殖器负责发现，工具负责执行具体的外部调用。

运行时数据流¶

flowchart TD
    main["main() 种子(-d/-u)"] --> addseed["add_seed()"]
    addseed --> assetgraph["AssetGraph.add_asset()<br/>新资产入库（去重）"]
    addseed --> queue["PriorityBreedingQueue.add()"]
    assetgraph --> run["run() → start() → _concurrent_breed()"]
    queue --> run
    run --> pool["ThreadPoolExecutor(max_tasks)"]
    pool --> getnext["queue.get_next(strategy)"]
    getnext --> process["_process_asset(asset)"]

    process --> check["深度/类型/资源/排除检查"]
    check -->|不通过| excluded["excluded"]
    check -->|通过| breeder["BreederFactory.get_breeder(type)"]
    breeder --> exec_node["breeder.execute(asset, ToolOrchestrator)"]
    exec_node --> tools2["外部工具 calls / 内部实现"]

    exec_node --> newloop["新资产循环"]
    newloop --> newasset["add_asset → add_edge(discovered)"]
    newasset --> hook["emit_hook(on_asset_discovered)"]
    hook --> qadd["queue.add()"]
    exec_node --> scannedhook["emit_hook(on_asset_scanned)"]

    qadd --> queue
    process --> empty{"队列空?"}
    empty -->|否| pool
    empty -->|是| done["completed → stop()"]
    done --> ckpt["save_checkpoint()"]
    done --> gen["OutputHandler.generate_output()"]

各模块职责¶

main.py — 引擎主控 + 入口¶

  • BreedingEngine：扫描生命周期状态机（initialized / running / completed / stopped / failed）、信号处理、事件总线、检查点、指标
  • CLI 解析与多语言初始化
  • 插件加载器：目录扫描、识别 on_* 钩子、manifest 解析、冲突处理、register_cli
  • --watch 监控循环

core/zsans_engine.py — 数据模型¶

  • Asset 类体系与归一化
  • PriorityBreedingQueue：策略队列
  • AssetGraph：线程安全拓扑存储与导出
  • DEFAULT_CONFIG：内置默认配置

core/output.py — 输出¶

  • OutputHandler：创建时间戳目录，生成 JSON / 两个 CSV / GraphML / 自包含 HTML 报告
  • run_dir 供插件与其他模块访问本次输出目录

core/tools/tools.py — 工具编排¶

  • ToolOrchestrator：工具探测、执行、结果解析、回退、并发控制、指纹识别（EHole/WhatWeb）、插件工具注册

core/breeders/breeders.py — 繁殖器¶

  • BreederFactory：按资产类型分发
  • 每个繁殖器调用一组工具产出新资产

core/i18n.py — 国际化¶

  • gettext 栈：语言加载、_() 翻译函数、当前语言查询

webapp.py + web_frontend.py — Web 控制台¶

  • 标准库 HTTP 服务器 + SSE 实时日志
  • 单文件 Vue 3 SPA，本地静态资源

扩展点¶

1. 新增资产类型¶

  1. 在 core/zsans_engine.py 定义子类、注册工厂
  2. 在 core/breeders/breeders.py 新增繁殖器
  3. 在 asset_types 配置开启开关与优先级
  4. 视需要在输出模块扩展列与颜色

2. 新增工具¶

  1. 在 core/tools/tools.py 新增 run_<name> 方法（探测 → 执行 → 解析）
  2. 或在插件中调用 register_tool(name, path, version, extra_args) 注册/覆盖外部工具
  3. 在 external_tools.paths / concurrency.tools 配置路径与并发

3. 新增行为 —— 插件系统（推荐）¶

无需改动主程序，实现 on_* 钩子即可接入扫描生命周期。详见插件开发。

线程模型¶

组件 线程
资产处理 ThreadPoolExecutor(concurrency.max_tasks)，线程前缀 zsans
工具执行 经 submit_task() 提交到线程池，各工具独立并发限制
Web 任务 每任务一个守护线程 zsans-web-<id>
信号 CLI 模式注册 SIGINT/SIGTERM 优雅停机；Web/后台模式不注册（register_signals=False）

停止链路¶

flowchart TD
    sig["SIGINT / POST stop / Ctrl+C"]
    req["_stop_requested = True"]
    state["config.state = 'stopped'"]
    shut["executor.shutdown(wait=False, cancel_futures=True)"]
    ckpt["save_checkpoint()"]
    gen["output_handler.generate_output()"]
    tools["tool_orchestrator.shutdown()"]

    sig --> req --> state --> shut
    shut --> ckpt --> gen --> tools

watch 与 stop 的耦合

stop() 故意不置全局 _stop_signaled，否则 --watch 完成首轮后会误判"收到信号"直接退出。真正信号只由信号处理器置位。
